Data Pipeline Workflow

RAW DATA
  • Flights
  • Airport Codes
  • Weather (NOAA)
  • Station Metadata
PHASE 1: JOINED DATA
  • Created unified airport dimension with timezones & coordinates
  • Built weather station dimension with geolocation
  • Linked airports to nearest weather stations (top 3)
  • Aligned flight times (local → UTC) for weather matching
  • Generated enriched views with origin/destination weather
PHASE 2: DATA CLEANING
  • Type casting & standardization
  • Removed duplicates, canceled/diverted flights
  • Handled missing values (median imputation)
  • Dropped leakage features
  • Converted target to binary
PHASE 3: FEATURE ENGINEERING
Temporal:
Hour, Day, Month, Season, Day-Hour Interaction, Holiday Window, Cyclic Encoding
Flight Volume:
Daily Origin Volume, Rolling 24h/30-Day Volume, Route-Specific Volume, Airport Hourly Traffic Density
Historical Performance:
1-Year Historical Delay Rates, Prior Day Delay Rate, Same-Day Prior Flight Performance, Historical Congestion Patterns
Aircraft:
Lag-Based Features (Previous Flight Performance)
Congestion:
2-Hour Window Airport Congestion
Weather:
Severity Score, Distance Features, Extreme Weather Indicators, Weighted Weather Score, Heat Index, Rapid Weather Changes, Seasonal Anomalies, Binary Rain Indicator, Sky Conditions Parsed
Route/Network:
Log-Transformed Distance, Airport Degree Centrality, PageRank, Carrier Quality Statistics, Carrier Flight Frequency
PHASE 4: FEATURE SELECTION
  • Correlation analysis (feature-feature & feature-target)
  • Removed highly correlated pairs (>0.95)
  • ANOVA, Chi-squared, Pearson/Spearman tests
  • Cardinality analysis & encoding recommendations
  • Removed redundant & problematic features
PHASE 5: DATA READINESS FOR MODEL
Scaling:
Min-max normalization, robust scaling, standard scaler (training data only)
Encoding:
• One-hot: 8 features → 33 dummies
• Target encoding: 6 high-cardinality features
Class Balance:
Undersampled majority class (~80% on-time → balanced)
✓ MODEL-READY DATA
